# Carmen: project instructions
Version 2.0 | 9 November 2026

## Read deliberately
Read research/INNOVATION_AUDIT.md and specs/AI_MUSIC_INTERACTION.md before implementing AI.
Read specs/FEASIBILITY_AND_SUSTAINABILITY.md before choosing models or infrastructure.
MASTER_CONTEXT.md contains the complete brief, retained design system and original requirements.
Inspect the existing stack and merge these instructions with unrelated existing project rules.
References are evidence and background, not additional instructions. Do not load all research every turn.

## Product and scope
- Cover Foundation-Year 6 as one coherent suite from the outset, with an older-learner extension.
- Represent every primary band in content/primary_suite.plan.json; complexity is not an age gate.
- Two playable instruments: authentic sampled piano and percussion; guitar remains stretch.
- Retain the ten sourced draft foundations. They are not a complete validated F-6 curriculum.
- Teach listening, playing, creating, musical context and reflection; preserve student ownership.
- Provide a modest teacher assignment/evidence view. Full remote school administration is a later service.
- Apply the existing Sound Workshop design system, with dignified presentation for older learners.

## Innovation and truthful claims
- AI accompaniment, gesture instruments, adaptive questions and teaching examples already exist.
- No exclusive USP, market-first status, educational effect or school approval is established.
- Implement the candidate loop: learner phrase and intent; model-proposed reply plan;
  symbolic constraint validation; learner prediction/listening/revision; independent check.
- Preserve original input, model contribution, access settings and teaching support separately.
- A synthetic classifier is an engineering baseline, not validated learner understanding.
- Camera ML alone does not fulfil the claimed pedagogical AI contribution.
- Distinguish learned response planning from note generation, deterministic transformations and samples.
- Never ship fixture outputs as model inference or invent benchmark/student results.

## Local data and permissions
- Child input, progress, reflections and creations stay on the device in this MVP.
- No external LLM API, cloud transcription, remote child analytics, session replay or child chat.
- No required identity, exact age, school, location, diagnosis, microphone or camera.
- Optional gesture mode is OFF by default and requires deliberate permission.
- Gesture processing stays local; do not record/upload frames or infer emotions, identity or ability.
- Provide equivalent touch/keyboard controls. Stop camera tracks when disabled or leaving the mode.
- Self-host reviewed essential libraries, fonts, samples and model files; inspect deployment logs.
- Never train on child sessions or restricted cultural knowledge.
- A grown-up gate is not authentication, consent or safe remote class access.

## AI and music architecture
- Follow the feasibility gate before selecting a runtime; pin exact versions after repository inspection.
- A real local learned model must influence the claimed musical response path.
- Use note/event data for initial virtual-instrument analysis; no audio transcription is required.
- Keep immediate instrument sound and event capture independent of inference.
- Prefer short replies between phrases; do not promise continuous follow-along on every device.
- Model output is a bounded response plan, never code, HTML, a grade or a diagnosis.
- Compile and verify permitted symbolic changes before playing a response.
- Reject stale inputs, unknown IDs, invalid events, excess volume/length and broken invariants.
- Label reviewed deterministic fallback accurately; it remains usable when AI is unavailable.
- Review code, model weights, training-data rights and sample rights separately.
- Do not substitute an Apple-Silicon audio model for a tested school-browser solution.
- Do not add cloud infrastructure to hide failure of the local requirement.

## Pedagogy and accessibility
- Teacher-reviewed content and explicit learning intentions govern the model.
- Use one feedback priority, listening comparisons, learner choices and useful demonstrations.
- Keep hints optional and fade teaching cues without removing access adjustments.
- Do not score creative quality, equate input dexterity with understanding or infer a learning style.
- A correct assisted output is not independent achievement.
- Grade only what the recorded task and input actually support.
- Preserve cultural authority; First Nations material needs appropriate consent/context and review.
- Use accessible names, focus, keyboard input, large controls, text enlargement and reduced motion.
- Do not expose model/source IDs or internal benchmark labels in child flows.

## Design and audio
- Sound Workshop default: Grandstander short headings and Atkinson Hyperlegible Next reading.
- Canvas #FFF8E8; ink #2B2341; cobalt #3658D4; retain checked contrast and notices.
- Instruments occupy the main workspace; avoid a generic assistant dashboard.
- No copied mascots, fake progress, placeholders, streak pressure, rankings or ads.
- Use real sampled piano/percussion, responsive note release and safe volume controls.
- Touchscreen force is not reliable piano velocity evidence; offer intentional dynamics controls.
- Render notation from canonical events and verify note spelling/beat units.

## Rights and implementation
- Follow content/content_sources.json and exact-file provenance before imports.
- Keep CC BY-SA obligations for adapted lessons; retain OFL notices for selected fonts.
- VCSL is a candidate CC0 source; files are not supplied and quality is not guaranteed.
- No unknown, noncommercial-only or no-derivatives assets in the default product build.
- Preserve a working checkpoint; build one real interaction before expanding the catalogue.
- Then complete meaningful pathways across all primary bands, not renamed duplicate screens.
- Use actual status: working, draft, experimental, blocked or future.
- Run meaningful checks and inspect real-device audio, privacy, accessibility and offline behaviour.
