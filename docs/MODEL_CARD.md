# Model card: carmen-timing-pattern-mlp v1.0.0

Numbers below come from `docs/model-metrics.json`, written by `npm run train`. Re-run that command to regenerate; do not hand-edit.

## Task
Describe the **timing pattern** of a played phrase from checker facts: `steady`, `early`, `late`, `speedingUp`, `slowingDown`, `uneven`. If fewer than three events were matched, the result is `insufficient` without running the model. If the top probability is below 0.5 the model **abstains** and the coach uses the rules baseline.

The pattern selects which verified musical reply the coach offers (for example, your own taps with a steady click under them, or the same at a slower tempo). It never changes the score, never sets access settings, and never produces text: the coach uses reviewed templates in `src/data/coach.json`.

## What it is not
- Not a diagnosis of a child, their attention, ability, hearing or any condition.
- Not a model of musical understanding. It describes timing evidence from one attempt.
- Not trained or tested on children. Not updated from children's sessions.
- Not a composer: it never writes notes for the learner.
- It does not know about device audio latency. A consistently "late" result can be caused by the device. Calibration is a known gap.

## Architecture
MLP 12 → 16 (tanh) → 6 (softmax), 310 parameters, about 6.5 KB as JSON. Pure TypeScript inference (`src/ai/mlp.ts`), no runtime library, bundled with the app so it works offline. Weights SHA-256 is recorded in `src/ai/model.weights.json` and `docs/model-metrics.json`.

## Features (schema 1.0.0, `src/ai/features.ts`)
Mean, median and spread of signed onset residuals (in beats), total drift across the phrase, mean absolute residual, fraction early, fraction late, second-half minus first-half residual, inter-onset-interval variation, detrended spread, fraction of expected events matched, and event count. No identity, age, time of day, location or device identifiers.

## Data
Seeded synthetic attempts from `src/ai/synth.ts` (seed 20261109). Each sample's label is the process that generated it (constant offset, drift, random spread, and so on), with jitter and 0–25% missed notes. Rhythm templates are split into **disjoint families**: train families 0–399 (12,000 samples), validation 10000–10099 (3,000), test 20000–20099 (3,000). Licence: generated by the project, released with the code.

## Results on held-out synthetic families (v1.0.0)
| | Model | Rules baseline |
|---|---|---|
| Accuracy | 0.953 (top-1) | 0.899 |
| Macro-F1 | 0.955 (abstain counted as wrong) | 0.897 |
| Abstain rate | 1.2% | — |
| Accuracy when answering | 0.961 | — |

Full confusion matrices are in `docs/model-metrics.json`. A second check in `src/ai/ai.test.ts` regenerates 1,800 samples from a different seed and family range and requires the model to beat 0.85 and match or beat the rules.

**Interpretation.** On synthetic data the learned model separates offset, drift and spread more reliably than hand thresholds, mainly on borderline cases. This shows the engineering works. It does not show that children's real timing looks like the generator, or that the model's replies help anyone learn. Those need a supervised trial with educators.

## Runtime
- Node 22 on the build container: about 1 µs per inference, 2.5 µs per feature extraction (20,000 runs).
- Browser timing is measured in the app and shown in Teacher Mode for each AI decision (`latencyMs`).
- Download: about 6.5 KB inside the main bundle.

## Intended use
Prototype coaching for Carmen's lessons: choosing between a small set of reviewed, verified musical replies after a short phrase. Teachers can see each decision, its evidence and whether the model or rules made it.

## Out of scope
Grading, ranking, placement, reports to parents or schools, any decision about a child outside the practice loop, and any use with real children before educator review and appropriate consent arrangements.
